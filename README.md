# Google C++ Style Plugin

Расширение для **Visual Studio Code**. Оно проверяет C++ код на соответствие
[Google C++ Style Guide](https://google.github.io/styleguide/cppguide.html), подчёркивает нарушения,
при наведении объясняет, что не так и как исправить, показывает число нарушений и умеет
исправлять код автоматически. Также можно настроить размер отступа: по Google это 2 пробела, но можно поставить 4 или любое другое число.

## Возможности

- **Подчёркивание нарушений** прямо в коде: жёлтые волнистые линии для предупреждений, синие для рекомендаций. Все нарушения также видны на вкладке **«Проблемы»** (Ctrl+Shift+M).
- **Объяснение при наведении.** Подсказка показывает, что именно не так в этой строке, суть правила, пример «❌ неправильно / ✅ правильно» и ссылку на раздел Google Style Guide.
- **Счётчик нарушений** в строке состояния: `⚠ Google Style: 12`. Если навести на него курсор, видна разбивка по типам и самые частые нарушения. Щелчок открывает меню расширения.
- **Быстрые исправления (Ctrl+.)** для каждого нарушения: исправить, переименовать, игнорировать строку (`// NOLINT`) или отключить правило.
- **Исправить всё** (Ctrl+Alt+G, кнопка 🔧 над редактором или контекстное меню): за один шаг исправляются отступы, пробелы, скобки, `NULL`, касты, порядок `#include`, header guard и т. д.
- **Исправить всё, включая имена:** переменные, функции, типы, константы и поля переименовываются по правилам Google (`itemCount` → `item_count`, `MAX_SIZE` → `kMaxSize`, `m_size` → `size_`).
- **Настраиваемый отступ**: команда «Изменить размер отступа» или настройка `googleCppStyle.indentSize`. Также настраиваются отступ `public:`, длина строки, лимит длины функции и важность каждого правила.
- **Проверка всего проекта**: все `.cpp/.h` файлы рабочей папки попадают на вкладку «Проблемы».
- **Отчёт по файлу**: список всех нарушений, сгруппированных по правилам, на панели «Вывод».
- **Автоисправление при сохранении** (`googleCppStyle.fixOnSave`) и режим **форматтера** для Shift+Alt+F (`googleCppStyle.formatter.enable`).
- **54 правила** в 6 группах: форматирование, пробелы, комментарии, именование, заголовки, возможности C++ (полный список ниже).
- Комментарии и строковые литералы, включая raw-строки `R"(...)"`, не проверяются как код. Разделители разрядов `1'000'000` поддерживаются.
- Работает без интернета и без внешних программ (Python, cpplint, clang-format не нужны).

## Установка

### Из файла .vsix
1. Скачайте `google-cpp-style-plugin-1.0.0.vsix`.
2. VS Code → панель **Extensions** (Ctrl+Shift+X) → `...` → **Install from VSIX...** → выберите файл.
3. Откройте любой `.cpp` или `.h` файл: проверка начнётся автоматически.

Или из терминала: `code --install-extension google-cpp-style-plugin-1.0.0.vsix`

### Из исходников
```bash
git clone https://github.com/Twiqsi/google-cpp-style-plugin
cd google-cpp-style-plugin
npm install
npm run compile
```
Нажмите **F5**: откроется окно **Extension Development Host** с запущенным расширением и тестовыми файлами из `test/fixtures`.

Собрать `.vsix`: `npm run package`

## Использование

| Действие | Как |
|---|---|
| Посмотреть, что не так | Навести курсор на подчёркнутый код |
| Исправить одно нарушение | Курсор на подчёркивание → **Ctrl+.** → выбрать исправление |
| Исправить весь файл | **Ctrl+Alt+G** или 🔧 над редактором, или ПКМ → «Исправить всё в файле» |
| Исправить файл вместе с именами | Палитра команд (Ctrl+Shift+P) → «Google Style: Исправить всё, включая имена» |
| Изменить размер отступа | Щелчок по счётчику в строке состояния → «Размер отступа» или «Google Style: Изменить размер отступа» |
| Проверить весь проект | «Google Style: Проверить весь проект» |
| Отчёт | «Google Style: Отчёт по текущему файлу» |
| Пропустить строку | В конце строки `// NOLINT` или `// NOLINT(имя-правила)`. Для следующей строки: `// NOLINTNEXTLINE` |

### Пример

```cpp
#include <iostream>
using namespace std;          // ⚠ using namespace запрещён

const int MAX_SIZE=100;       // ⚠ имя константы → kMaxSize; ⚠ пробелы вокруг =

int calcSum(int firstArg,int b)   // ⚠ имя функции → CalcSum; ⚠ имя параметра → first_arg
{                                 // ⚠ { должна быть на предыдущей строке
    int *ptr = NULL;              // ⚠ отступ 2; ⚠ int* ptr; ⚠ nullptr
    return (firstArg+b);          // ⚠ лишние скобки в return; ⚠ пробелы вокруг +
}
```

После **«Исправить всё, включая имена»**:

```cpp
#include <iostream>
using namespace std;

const int kMaxSize = 100;

int CalcSum(int first_arg, int b) {
  int* ptr = nullptr;
  return first_arg + b;
}
```

`using namespace std;` автоматически не удаляется: тогда пришлось бы дописывать `std::` по всему файлу. Такие места остаются подчёркнутыми, и подсказка объясняет, что сделать.

## Настройки

| Настройка | По умолчанию | Описание |
|---|---|---|
| `googleCppStyle.enable` | `true` | Включить проверку |
| `googleCppStyle.indentSize` | `2` | **Размер отступа** в пробелах (например, `4`) |
| `googleCppStyle.accessModifierIndent` | `1` | Сдвиг `public:`/`private:` относительно `class` |
| `googleCppStyle.continuationIndent` | `4` | Отступ перенесённых строк при автоисправлении |
| `googleCppStyle.lineLength` | `80` | Максимальная длина строки |
| `googleCppStyle.maxFunctionLines` | `40` | Длина функции, после которой выдаётся рекомендация |
| `googleCppStyle.severity` | `warning` | Как показывать нарушения: `error` / `warning` / `info` / `hint` |
| `googleCppStyle.rules` | `{}` | Важность или отключение отдельных правил, например `{"line-length": "off"}` |
| `googleCppStyle.lintOnType` | `true` | Проверять во время набора |
| `googleCppStyle.fixOnSave` | `false` | Исправлять форматирование при сохранении |
| `googleCppStyle.fixAll.renameIdentifiers` | `false` | «Исправить всё» также переименовывает идентификаторы |
| `googleCppStyle.useLanguageServerRename` | `true` | Переименовывать через расширение C/C++ во всех файлах, если оно установлено |
| `googleCppStyle.formatter.enable` | `false` | Использовать как форматтер (Shift+Alt+F) |
| `googleCppStyle.hover` | `true` | Подробная подсказка при наведении |

Пример `.vscode/settings.json` для курса, где принят отступ 4:

```json
{
  "googleCppStyle.indentSize": 4,
  "googleCppStyle.accessModifierIndent": 2,
  "googleCppStyle.rules": {
    "exceptions": "off",
    "naming-function": "error"
  }
}
```

## Правила

### Форматирование

| Правило | ID | Что проверяет |
|---|---|---|
| Отступы | `indentation` | Каждый уровень вложенности сдвигается на заданное число пробелов (по Google — 2, размер меняется в настройках). Содержимое namespace не сдвигается, `public:`/`private:` сдвигаются на 1 пробел, `case` — на один уровень внутри `switch`, а код под `case` — ещё на один. Перенесённые строки (продолжения) должны быть сдвинуты сильнее начала инструкции. |
| Табуляция | `tab` | Используйте только пробелы. Символы табуляции запрещены — настройте редактор так, чтобы Tab вставлял пробелы. |
| Длина строки | `line-length` | Строка должна быть не длиннее заданного лимита (по Google — 80 символов). Исключения: #include, header guard, using-объявления и комментарии со ссылкой, которую нельзя разорвать. |
| Пробелы в конце строки | `trailing-whitespace` | В конце строки не должно быть пробелов и табуляций. |
| Конец файла | `end-of-file` | Файл должен заканчиваться ровно одним переводом строки, без пустых строк в конце. |
| Пустые строки | `blank-lines` | Пустые строки используйте экономно: не ставьте их в начале и в конце блока, не ставьте несколько подряд и не оставляйте пустую строку сразу после `public:`/`private:`. |
| Пустая строка перед public/private | `access-specifier-blank-line` | Перед `public:`, `protected:` и `private:` (кроме первого в классе) ставится пустая строка. В маленьких классах это необязательно. _(по умолчанию: info)_ |
| Директивы препроцессора | `preprocessor-indent` | Символ `#` всегда стоит в начале строки, даже внутри функций. Отступ можно ставить после `#`. |
| Открывающая скобка `{` | `brace-same-line` | Открывающая фигурная скобка ставится в конце строки с объявлением/условием, а не на отдельной строке. |
| `else` на одной строке с `}` | `else-same-line` | `else` (и `catch`) пишутся на той же строке, что и закрывающая `}` предыдущего блока. |
| Скобки в if-else | `braces-if-else` | Без фигурных скобок можно писать только короткий одиночный if/for/while. Если есть `else` — фигурные скобки обязательны во всех ветках. |
| Пустое тело цикла | `empty-loop-body` | Пустое тело цикла пишется как `{}` или `continue;`, а не одиночной `;` — её легко спутать с do-while. |
| Комментарий в конце namespace | `namespace-end-comment` | Многострочный namespace закрывается комментарием с его именем. |
| Одна инструкция на строке | `one-statement-per-line` | Не пишите несколько инструкций в одной строке — каждая на своей строке. |
| Длинная функция | `function-length` | Google рекомендует короткие функции: если функция длиннее ~40 строк, подумайте, нельзя ли разбить её на части. Лимит настраивается. _(по умолчанию: info)_ |
| `default` в switch | `switch-default` | Если switch не по enum, в нём всегда должна быть ветка `default`. _(по умолчанию: info)_ |

### Пробелы

| Правило | ID | Что проверяет |
|---|---|---|
| Пробел после if/for/while | `space-after-keyword` | После `if`, `for`, `while`, `switch`, `catch` ставится пробел перед `(`. |
| Пробел перед `{` | `space-before-brace` | Перед открывающей фигурной скобкой блока всегда ставится пробел. |
| Пробелы внутри скобок | `paren-spacing` | Внутри круглых скобок не ставят пробелы сразу после `(` и перед `)`. |
| Пробел перед `(` вызова | `function-call-space` | Между именем функции и открывающей скобкой пробела нет — ни в вызове, ни в объявлении. |
| Пробелы вокруг операторов | `operator-spacing` | Операторы присваивания (`=`, `+=`, ...) всегда окружены пробелами. Сравнения (`==`, `!=`, `<=`, `>=`) и логические (`&&`, `\|\|`) тоже пишутся с пробелами. |
| Пробел после запятой | `comma-spacing` | После запятой ставится пробел, перед запятой — нет. |
| Пробелы у `;` | `semicolon-spacing` | Перед `;` пробела нет, после `;` внутри `for (...)` — есть. |
| Двоеточие в range-for | `range-for-colon` | В range-based for вокруг `:` ставятся пробелы с обеих сторон. |
| Пробел после template | `template-space` | Между `template` и `<` ставится пробел. |
| Положение `*` и `&` | `pointer-alignment` | В объявлениях `*` и `&` прижимаются к типу, а от имени отделяются пробелом: `char* c`, `const std::string& s`. Нельзя объявлять несколько переменных в одной строке, если среди них есть указатель или ссылка. |

### Комментарии

| Правило | ID | Что проверяет |
|---|---|---|
| Оформление комментариев | `comment-spacing` | После `//` ставится пробел. Перед комментарием в конце строки кода — минимум два пробела. |
| Формат TODO | `todo-format` | TODO пишется заглавными и с указанием автора или задачи в скобках: `// TODO(имя): что сделать`. |
| Лицензия в начале файла | `copyright` | Каждый файл начинается с комментария с лицензией/авторством. По умолчанию правило выключено. _(по умолчанию: off)_ |

### Именование

| Правило | ID | Что проверяет |
|---|---|---|
| Имена типов | `naming-type` | Классы, структуры, enum, typedef и using-псевдонимы называются в PascalCase: каждое слово с заглавной буквы, без подчёркиваний. |
| Имена функций | `naming-function` | Функции называются в PascalCase: `AddTableEntry()`. Исключение — геттеры и сеттеры, их можно называть как переменные: `int count() const`, `void set_count(int count)`. |
| Имена переменных | `naming-variable` | Переменные и параметры функций — в snake_case: строчные буквы, слова через подчёркивание. |
| Имена полей класса | `naming-member` | Поля `class` — в snake_case с подчёркиванием в конце: `table_name_`. Поля `struct` — в snake_case без подчёркивания в конце. |
| Имена констант | `naming-constant` | Константы (`const`/`constexpr` со статическим временем жизни: глобальные, в namespace, `static` поля класса) называются с `k` и PascalCase: `kDaysInAWeek`. |
| Имена значений enum | `naming-enumerator` | Значения enum называются как константы — `kEnumName`, а не как макросы `ENUM_NAME`. |
| Имена namespace | `naming-namespace` | Имена пространств имён — в snake_case (строчные буквы и подчёркивания). |
| Имена макросов | `naming-macro` | Макросы называются ЗАГЛАВНЫМИ_БУКВАМИ_С_ПОДЧЁРКИВАНИЯМИ. А лучше вообще обходиться без них. |
| Имена параметров шаблона | `naming-template-param` | Типовые параметры шаблона называются как типы — в PascalCase (`T`, `ValueType`). |

### Заголовки

| Правило | ID | Что проверяет |
|---|---|---|
| Header guard | `header-guard` | Каждый заголовочный файл защищается от повторного включения через `#ifndef` / `#define` / `#endif` с именем вида `<ПУТЬ>_<ФАЙЛ>_H_`. `#pragma once` в Google не используется. |
| Порядок #include | `include-order` | Порядок: свой заголовок → системные C-заголовки (`<stdio.h>`) → стандартная библиотека C++ (`<vector>`) → другие библиотеки → заголовки проекта (`"..."`). Группы разделяются пустой строкой, внутри группы — по алфавиту. Не используйте `.` и `..` в путях. |
| <bits/stdc++.h> | `include-bits` | `<bits/stdc++.h>` — нестандартный заголовок GCC. Подключайте только то, что используете (`<iostream>`, `<vector>`, ...). |

### Возможности C++

| Правило | ID | Что проверяет |
|---|---|---|
| using namespace | `using-namespace` | `using namespace ...;` запрещён: он засоряет пространство имён. Пишите `std::` явно или `using std::cout;`. |
| Объявления в namespace std | `namespace-std` | Ничего не объявляйте в `namespace std` — это неопределённое поведение. |
| C-style приведение типов | `c-style-cast` | Не используйте приведения вида `(int)x`. Используйте `static_cast<int>(x)` (или `reinterpret_cast`/`const_cast` для указателей). Исключение — приведение к `(void)`. |
| NULL вместо nullptr | `nullptr` | Для указателей используйте `nullptr`, а не `NULL` или `0`. |
| Целочисленные типы | `integer-types` | Из встроенных целых типов используется только `int`. Если нужен другой размер — берите типы из `<cstdint>`: `int16_t`, `int64_t`, `uint64_t` и т.д. вместо `short`, `long`, `long long`. |
| explicit-конструктор | `explicit-constructor` | Конструктор, который можно вызвать с одним аргументом, помечается `explicit`, чтобы не было неявных преобразований. Исключения: копирующий/перемещающий конструктор и `std::initializer_list`. |
| virtual вместе с override | `virtual-override` | При переопределении пишите ровно одно из `override` или `final`, без `virtual`. |
| Скобки в return | `return-parens` | Не оборачивайте всё выражение в return в лишние скобки: `return` — не функция. |
| Префиксный ++/-- | `preincrement` | Используйте префиксную форму `++i`/`--i`, если результат постфиксной формы не нужен. _(по умолчанию: info)_ |
| Глобальные объекты | `global-object` | Глобальные и статические объекты с нетривиальным деструктором (`std::string`, `std::vector`, `std::map`...) запрещены. Используйте `constexpr`, `const char[]`, `std::string_view` или локальные переменные. |
| Макрос-константа | `macro-constant` | Избегайте макросов. Вместо `#define N 100` используйте `constexpr int kN = 100;`. _(по умолчанию: info)_ |
| Исключения | `exceptions` | В коде Google исключения C++ не используются. Если преподаватель требует исключения — отключите это правило. _(по умолчанию: info)_ |
| RTTI | `rtti` | Избегайте `dynamic_cast` и `typeid` — обычно лучше виртуальные функции. _(по умолчанию: info)_ |

## Как это устроено

```
src/
├── extension.ts      — связь с VS Code: диагностики, подсказка, быстрые исправления,
│                       строка состояния, команды, настройки
└── core/             — ядро проверки (не зависит от VS Code)
    ├── lexer.ts      — «маскирует» комментарии и строки, сохраняя позиции символов
    ├── linter.ts     — все проверки: отступы и скобки, пробелы, имена, include, header guard
    ├── fixer.ts      — применение исправлений и «Исправить всё»
    ├── naming.ts     — проверка и преобразование стилей имён (PascalCase, snake_case, kConstant…)
    ├── rules.ts      — описания правил, примеры и ссылки на руководство
    └── types.ts      — общие типы и настройки по умолчанию
test/                 — тесты ядра, смоук-тест расширения и примеры C++ файлов
tools/lint-cli.js     — проверка файлов из командной строки без VS Code
```

Проверка устроена так:
1. **Лексер** заменяет пробелами содержимое комментариев и строковых литералов. Поэтому `"a=b"` и `// x=1` не дают ложных срабатываний, а номера колонок совпадают с оригиналом.
2. **Структурный проход** отслеживает фигурные и круглые скобки и границы инструкций. Для каждой строки он вычисляет ожидаемый отступ и тип блока: namespace, class, switch, enum, функция. Отсюда проверки отступов, `public:`, `case` и правило «содержимое namespace не сдвигается».
3. **Построчные правила** смотрят пробелы, операторы, касты, `NULL` и т. п. **Разбор объявлений** определяет, что объявлено (тип, функция, переменная, поле, константа), и проверяет имя по правилам этой категории.
4. У каждого нарушения есть позиция, текст и, если возможно, **исправление** (набор правок текста) или **переименование**. «Исправить всё» применяет исправления в несколько проходов: одно исправление может открыть другое. Например, после переноса `{` пересчитываются отступы.

Тесты: `npm test` (ядро), `node test/smoke.js` (расширение целиком на имитации API VS Code).

## Ограничения

- Расширение анализирует текст и не строит полное синтаксическое дерево C++, как компилятор. В очень необычных конструкциях (сложные макросы, шаблонная магия) возможны редкие пропуски или ложные срабатывания. Такую строку можно пометить `// NOLINT`.
- Правила, которые требуют понимать смысл кода, не проверяются. Например, «используйте `const` где возможно», порядок объявлений в классе, качество комментариев.
- Переименование в режиме «Исправить всё» меняет имена в текущем файле. Если имя используется в других файлах, применяйте быстрое исправление «Переименовать» при установленном расширении C/C++: оно меняет имя во всём проекте.
